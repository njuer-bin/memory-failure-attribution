# 盲评评分卡（供第二标注人独立填写）

适用文件：`validation_B_16.csv`

## 0. 边界（务必先读）

- 你只填这 6 列：`realism_1_5`、`status_clarity_1_5`、`rule_clarity_1_5`、`distortion_plausible_1_5`、`stake_severity_1_5`、`notes`。
- `only_status_differs` 已预填，**不要改**；若你认为填错，记为分歧，不要动手。
- 只依据本表内的 `evidence / rule / request / present / omitted / distorted` 文本判断。
- 不得查阅任何其他已填写的表、标注结果、答案文件、条目源文件，也不要与他人讨论具体行。
- 每行独立判断，分值只能是 1–5 的整数。

## 1. realism_1_5（场景真实度）

| 分 | 锚点 |
|---|---|
| 1 | 荒诞、现实中不可能发生 |
| 3 | 可能发生，但略显刻意 |
| 5 | 现实中常见、完全自然 |

评的是 `request` 描述的场景本身是否像真实用户会提出的事。不评文本写得好不好。

## 2. status_clarity_1_5（状态清晰度）

| 分 | 锚点 |
|---|---|
| 1 | 无状态或自相矛盾，无法判断用户是否已决定 |
| 3 | 能推断出决定，但有保留（表述不直接/有歧义） |
| 5 | 一眼可定，`evidence` 明确表达了决定 |

只看 `evidence` 是否清楚表达"已决定做 X"。动作对象有歧义时降级。

## 3. rule_clarity_1_5（规则确定性）

| 分 | 锚点 |
|---|---|
| 1 | 规则无法决定该动作 |
| 3 | 基本清楚，但存在一个边界不清之处 |
| 5 | 完全确定，规则与动作一一对应、要素齐全 |

只看 `rule` 文本能否唯一决定 `request` 里的动作（对象、金额、方向、接收方等要素是否写全）。

## 4. distortion_plausible_1_5（扭曲可信度）

| 分 | 锚点 |
|---|---|
| 1 | 荒谬或无关，不像是摘要改写造成的 |
| 3 | 有可能，但生硬 |
| 5 | 自然的、典型的过度承诺/状态翻转错误 |

自问：把 `evidence` 里的"已决定做 X"改写成 `distorted` 里的说法，像不像一次真实的摘要错误？

- 评的是**这个错误像不像改写造成的**，不是"这个变体是否严重"。
- 直接取反（做↔不做、取消↔保留）通常比引入新事实更自然。
- 中性填充句（"This was discussed recently…"）不算状态变化。

## 5. stake_severity_1_5（后果严重度）

| 分 | 锚点 |
|---|---|
| 1 | 微不足道 |
| 3 | 几百元量级 / 可撤销的小麻烦 |
| 5 | 健康风险 / 大额金额 / 未授权访问等严重且难撤销的后果 |

评 `request` 里的**动作**被误执行或漏执行的后果，不是话题本身。
例：仅是"讨论保险"不等于"取消保险"；是否真的执行动作才是评分对象。

## 6. notes 写法

每行一句，不空。建议格式：

```
P=<request 动作简述>; distorted 改成<简述>; 仅状态差异? 是/否; <一句评分理由>
```

- 不要写"gold""正确答案"之类的字段。
- 某列不适用时给最低可辩护分，并在 notes 说明原因。
- 中文或英文均可，一行写完。

## 7. 通用坑位

- 不评写作质量、帮助性、格式。
- `distortion_plausible` 评"像不像改写错误"，不是"严不严重"。
- `stake_severity` 评动作后果，不是话题。
- 中性填充句不算状态变化。
- 不要留空。

- 5 个评分列取值都在 1–5 的整数。
