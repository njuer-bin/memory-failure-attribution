# 2026-10-12 — F4 attribution audit fix

## Problem

The lifecycle attribution definition treats `F4_RETRIEVAL` as covering both retrieval loss and rerank loss. The post-hoc audit therefore must not report an F4 warning when retrieval succeeds but rerank loses the gold evidence.

## Fix

Added `experiments/audit_attributions.py` with the corrected rule:

- retrieval missing -> valid F4
- rerank missing -> valid F4
- both found -> audit warning
- neither missing/unknown -> audit warning

The warning is now named `F4_WITHOUT_RETRIEVAL_OR_RERANK_LOSS`.

## Regression tests

Added `tests/test_audit_attributions.py` covering:

1. retrieval-only loss;
2. rerank-only loss;
3. both stages found;
4. non-F4 attribution.

The test suite should be run locally before using the audit result for research conclusions.

## Research significance

This change does not alter the core attribution algorithm in `experiments/run_oracle_experiments.py`. It only aligns the audit layer with the already-defined F4 semantics, preventing false warnings for rerank-only failures.
