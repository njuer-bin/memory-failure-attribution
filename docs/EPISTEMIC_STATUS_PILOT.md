# Epistemic Status Preservation under Conversational Memory Compression — Pilot Protocol

**Status:** pre-registration-style pilot protocol; no empirical result has been collected yet.
**Branch:** `research/epistemic-compression-pilot`
**Date:** 2026-11-11

## 1. Research question

Does conversational memory compression change the epistemic/commitment status attached to a proposition, even when the proposition itself remains recognizable?

This pilot deliberately narrows the broad "epistemic status loss" idea. It does not propose a new memory architecture. It measures transformations from a user utterance to a compressed memory.

## 2. Falsifiable hypotheses

- **H1 (status distortion):** status classification accuracy on compressed memories is lower than on the corresponding raw utterances.
- **H2 (assertion inflation):** among non-factual inputs, compression increases the probability that the resulting memory is interpreted as a definite fact.
- **H3 (content/status dissociation):** some errors retain the proposition while changing its status; these cannot be counted as ordinary proposition omissions.
- **H4 (pipeline localization):** the compression effect remains after subtracting the same model's status-classification error on raw utterances.

A null result is informative: if compressed memories are no worse than raw utterances, or if all apparent errors are explained by the raw-input baseline, the central claim is not supported.

## 3. Controlled variables

Each proposition is rendered in six status conditions:

1. `FACT`: already happened / currently true.
2. `UNCERTAIN`: possible, not confirmed.
3. `HYPOTHETICAL`: conditional scenario, not an asserted plan.
4. `INTENTION`: intended future action.
5. `NEGATED_INTENTION`: explicitly not intended.
6. `UNDECIDED`: no decision has been made.

The proposition topic is held constant within each six-item block. Only the linguistic status frame changes. The initial corpus is Chinese, first-person, and single-turn to keep the pilot interpretable.

## 4. Conditions

For each utterance:

- **Raw:** an independent judge classifies the original utterance.
- **Compressed:** a writer model creates a concise memory using a neutral memory-writing instruction; an independent judge classifies the resulting memory.
- **Gold:** the dataset's human-authored status label is the reference label. Gold is not generated by a model.

The raw and compressed classifications use the same judge model and prompt. This does not eliminate judge bias, but paired raw-vs-compressed comparison controls for a portion of the judge's baseline difficulty.

## 5. Metrics

- **Raw Status Accuracy:** accuracy of judge labels on original utterances.
- **Compressed Status Accuracy:** accuracy of judge labels on compressed memories.
- **Status Preservation:** fraction of compressed memories whose judged status matches the gold status, among cases where the proposition is retained.
- **Assertion Inflation Rate:** fraction of non-`FACT` inputs classified as `FACT` after compression.
- **Negation Flip Rate:** fraction of `NEGATED_INTENTION` inputs classified as `INTENTION` or `FACT`.
- **Proposition Omission Rate:** fraction of compressed memories judged as not retaining the proposition.
- **Net Compression Effect:** paired compressed error rate minus raw error rate.

Do not merge proposition omission and status distortion into one metric. Report both denominators.

## 6. Pilot size and stopping rule

Default pilot: 10 proposition topics × 6 statuses = 60 utterances. The script supports a larger run via `--limit-base`.

This is a pipeline sanity check, not a confirmatory benchmark. Do not make significance or generalization claims from this sample. If the pilot shows a plausible effect, expand to at least 30–50 topics, manually review a stratified sample, and add natural multi-turn conversations before making a paper claim.

## 7. Model setup

Writer and judge model can be configured independently. Use a separate judge model when it is available locally; otherwise the same-model pilot is only a first-pass diagnostic. The runner calls a local Ollama-compatible endpoint (default `http://127.0.0.1:11434/api/chat`). Default model: `qwen2.5:7b`. No external API, training, or base-model fine-tuning is required.

Recommended first run on the user's local RTX 5060 Laptop:
```bash
python -m experiments.epistemic_status_pilot --writer-model qwen2.5:7b --judge-model qwen2.5:7b --limit-base 10
```

For a smaller smoke test:
```bash
python -m experiments.epistemic_status_pilot --writer-model qwen2.5:7b --judge-model qwen2.5:7b --limit-base 2 --max-retries 1
```

## 8. Validity threats and safeguards

1. **Judge confound:** report Raw and Compressed separately; inspect disagreements manually. The same small model can share writer/judge biases.
2. **Synthetic-language confound:** this is a controlled pilot only. Follow with natural multi-turn dialogue and human annotations.
3. **Prompt sensitivity:** freeze and version prompts; do not tune them after inspecting the test outputs.
4. **Writer instruction confound:** the writer prompt does not explicitly name the six target labels or tell the model to preserve epistemic status.
5. **Topic ambiguity:** each topic uses the same lexical proposition across its six frames; manually inspect generated utterances before scaling.
6. **Status ontology limitation:** the six labels are operational categories, not a complete theory of epistemic modality.
7. **No causal overclaim:** a difference in this setup supports a compression-associated distortion under this model/prompt, not a universal claim about all memory systems.

## 9. Decision criteria

Proceed to a larger study only if:
- compressed status accuracy is meaningfully below raw status accuracy, or assertion inflation is non-trivial;
- a substantial portion of errors retain the proposition but alter its status;
- manual review confirms the evaluator is not simply misreading the source utterance;
- the effect is reproducible across at least two writer configurations or model sizes.

Stop or reformulate if the apparent effect disappears after raw-baseline correction or is dominated by proposition omission.

## 10. Reproducibility outputs

The runner writes:
- `results/epistemic_status_pilot/pilot.jsonl`: one record per input utterance;
- `results/epistemic_status_pilot/summary.json`: aggregate metrics and run configuration.

The output records prompts, model names, raw writer text, judge labels, and errors for auditability. Do not edit raw outputs manually; create adjudicated annotations in a separate file.
